\begin{abstract}
We classify self-reported heart disease in the 2015 BRFSS survey using
six numerical methods and a NumPy gradient-boosted tree ensemble. The
selected GBDT improves validation F1 from 0.4386 for logistic
regression to 0.4462. On the test set, logistic regression scores
0.449 F1 and GBDT scores 0.454.
\end{abstract}

\section{Introduction}

Cardiovascular disease is a major public-health concern, and the 2015
Behavioral Risk Factor Surveillance System (BRFSS) provides a large survey
for studying associated health factors~\cite{cdc2015}. Its 321 predictors
cover demographics, behaviors such as smoking and physical activity,
reported conditions such as diabetes and hypertension, and healthcare use.
The course release has 328,135 labeled respondents and 109,379 unlabeled
test respondents, while the target variable \texttt{\_MICHD} indicates a self-reported history of coronary heart disease or heart attack.

This dataset mixes numeric quantities, categorical answer codes, and
structured missingness. For example, \texttt{PHYSHLTH}=88 means zero days,
while 77 and 99 mean an unknown or refused answer. Codebook-based rules drop
14 survey-design variables, two duplicate variables, and 14 raw mixed-unit
variables with computed replacements; they also convert units and fill
numeric values implied by skipped questions. This leaves 56 numeric and 235
categorical predictors. Unknown and refused categorical answers remain
separate categories. Moreover, only 8.83\% of training labels are positive showing a clear data unbalance.

Linear models such as logistic regression are common baselines for tabular
classification, while tree ensembles can capture nonlinear effects and
interactions. Gradient-boosted decision trees (GBDT) are well suited to
these survey data because they can split the cleaned variables directly
and learn where to route missing answers
~\cite{chen2016xgboost,ke2017lightgbm}. We then compare both approaches.

\section{Methods}

\subsection{Linear baselines.}
We implement the six methods required by the project as linear
baselines. Let $X$ include an intercept, let $y\in\{0,1\}^N$, and
write $z=Xw$. The methods minimize either squared error or logistic
loss:
\begin{align}
 L_{\mathrm{MSE}}(w)&=\frac{\lVert Xw-y\rVert_2^2}{2N},\\
 L_{\mathrm{log}}(w)&=\frac1N\sum_{i=1}^{N}
       \bigl[\log(1+e^{z_i})-y_i z_i\bigr].
\end{align}

For MSE, gradient descent (GD) uses the full gradient in
$w\leftarrow w-\gamma\nabla L_{\mathrm{MSE}}(w)$, while stochastic GD
(SGD) uses one sampled row per update. Least squares instead uses a
pseudoinverse of $X^\top X$, which is singular for our one-hot design;
ridge adds a regularizer $\lambda\lVert w\rVert_2^2$ and solves
$(X^\top X+2N\lambda I)w=X^\top y$. The other two methods minimize logistic loss by GD, with or without
the same $L_2$ penalty.

In the experiments, MSE GD uses 100 steps at $\gamma=0.02$ and SGD
uses $10^6$ single-row steps at $\gamma=5\cdot10^{-6}$. Both logistic
methods use 300 steps at $\gamma=0.1$; ridge and regularized logistic
regression use $\lambda=10^{-3}$.

\subsection{Gradient-Boosted Decision Trees (GBDT).}
GBDT models log-odds as an additive sum of trees, starting from the
training prevalence: $F_{t+1}(x)=F_t(x)+\eta f_t(x)$
~\cite{friedman2001greedy}. Each tree is fitted to reduce logistic loss.
Our NumPy code uses the loss gradients and Hessians to score candidate
splits and leaf values~\cite{chen2016xgboost}. It bins each cleaned
variable into at most 64 values, so split search uses compact
histograms~\cite{ke2017lightgbm}. Missing answers get a separate bin,
routed to whichever branch gives greater loss reduction. Depth-5
trees can capture interactions between survey answers. We use 550
trees, $\eta=0.05$, leaf $L_2$ penalty 10, minimum child Hessian 5,
and row/feature fractions 0.7/0.3; logits from seeds 0--2 are averaged.

\subsection{Data processing}\label{data_proc}

Each fold fits preprocessing on training rows and applies it to
validation rows. Linear models fill
missing numeric values with training medians, add missingness flags,
one-hot encode categories seen at least 30 times, and standardize the
resulting $\sim1{,}530$ columns. GBDT instead splits the 291 cleaned
variables directly and learns how to route missing values.

\subsection{Validation}
Only 8.83\% of labels are positive, so predicting all negatives gives
91.17\% accuracy but zero positive-class F1. We therefore report F1
and threshold-independent ROC AUC. The numerical baselines use five
shuffled folds (seed 42), with each decision threshold fitted on
training scores. The GBDT comparison repeats five folds with split
seeds 42--44; each scored fold uses a threshold chosen from the other
folds' out-of-fold predictions. Test F1 comes from submitted predictions
scored against hidden labels.

\paragraph{Model choice and refinements.}
The five-fold baseline table and the 15-fold model comparison use
different threshold procedures, so their F1 values should be read
within each table. On the 15 shared folds, the selected three-seed GBDT
improves F1 over logistic regression by 0.0077 (corrected 95\% interval
$[0.0038,0.0115]$)~\cite{nadeau2003inference}. The test submissions
score 0.449 F1 for logistic regression and 0.454 for this GBDT.

The nine single-GBDT runs span 0.4449--0.4469 F1; averaging seeds adds
only 0.0001 over one selected seed. The feature bag uses answer counts
and target-ordered codes and reaches 0.4474, but its paired gain is
only 0.0011 (corrected $t=1.51$). Other bags and blends in
Table~\ref{tab:advanced} show similarly small gains. A four-config
bag gained 0.0020 in one five-fold comparison, with an interval that
includes zero; using logistic predictions as a GBDT input gave
0.4456--0.4460, and mixing feature and config bags gave 0.4467.
We retain the three-seed model because no alternative shows a reliable
CV gain and \texttt{run.py} reproduces its test submission. Model
selection used these same folds, so CV may overestimate performance.

\subsection{Further GBDT checks}
Other depth, sampling, binning, and child-Hessian changes show no clear
gain. Starting GBDT from logistic predictions performs worse
(best-stage F1 0.4439).

Reducing the learning rate to 0.02 with about 2,000 trees lowers
validation log-loss from 0.21377 to 0.21349, but nested F1 stays near
0.4456. We therefore use rate 0.05 and 550 trees, within a flat
500--900-tree region; extending the default model to 2,000 trees
overfits (nested F1 0.4323). Depth-one trees score 0.4417 nested F1
versus 0.4457 for the selected depth-five single model, although other
settings differ. In separate ablations, depth two reaches best-stage
F1 0.4445, while removing \texttt{HAREHAB1} yields 0.4372. Best-stage F1 chooses its
threshold on the evaluated fold and is optimistic relative to nested F1.

\section{Conclusions}
Fold-fitted encoding gives a useful linear baseline, but GBDT provides
the main F1 gain. More complex ensembles and features show no reliable
CV improvement. The final \texttt{run.py} refits three GBDTs on all
labeled rows, averages their logits, and applies threshold 0.2166 to
\texttt{x\_test.csv}; its reported test F1 is 0.454.

This is a retrospective survey task. All 773 training respondents who
answered \texttt{HAREHAB1}, a question about rehabilitation after a
heart attack, are positive. That signal limits interpretation of the
result as prospective clinical risk prediction.
