## How it works

```
raw CSVs ─(part 2, once)─► clean.npz ─(part 3: transforms → model)─► CV scores / submissions
```

| Part | Entrypoint | Logic lives in | Produces |
|---|---|---|---|
| 1 · EDA | `notebooks/01_eda.ipynb` | `p1/eda.py` | insights, figures in `report/figures/` |
| 2 · Cleaning (once) | `notebooks/02_cleaning.ipynb` | `p1/cleaning.py` | `data/processed/clean.npz` |
| 3 · Transforms + models | `uv run p1 …` with a preset from `configs/` | `p1/transforms.py` (3.1), `p1/models.py` (3.2) | `outputs/` |
| Final submission | `uv run run.py` | all of the above | the best submission's CSV |

**Notebooks explore, `p1/` decides.** Use notebooks to look at the data and try ideas. Once a piece of logic becomes part of the final pipeline, it moves into a `.py` file in `p1/` and the notebook imports it. For part 2: explore in the notebook, write the rules you settle on in `p1/cleaning.py`, and let the notebook's last cell call `build_clean_dataset()`. That way `run.py` can rebuild everything from the raw CSVs, which the course requires (it rebuilds `clean.npz` first), and git diffs stay readable. `p1` can be imported from any folder because uv installs the project into `.venv`.

**Part 2 or part 3.1? Ask whether the step learns anything from the data.**
- **No**: fixed rules from domain knowledge or the BRFSS codebook → **part 2**, done once. E.g., drop ID/date columns, turn "Don't know / Refused" codes (7, 9, 77, 99…) into NaN.
- **Yes**: it needs a mean, a median, a std, a whitening matrix, the labels… → **part 3.1 transform**. E.g., fill NaNs with the median, standardize, whiten.
- Also make a step a 3.1 transform if you want to switch it on and off in experiments. That's how you get the ablation table the report asks for.

This matters because 3.1 transforms are re-fitted on the training folds only, so no validation data leaks into them, and their fitted values are saved together with the model.

**Part 3: a pipeline = transforms + one model.** `fit(x, y)` fits each transform in order on the training data, then the model. `predict(x)` applies the already-fitted transforms, then the model. So "whitening + linear regression" is trained, saved and used as one object. It's the same `fit`/`predict` interface as scikit-learn, which you'll use in Project 2.

Each preset in `configs/` describes one pipeline. The format is TOML: it's readable, allows comments, and Python's standard library can read it. YAML would need an external package, which the course forbids.

```toml
# configs/ridge_poly.toml
transforms = ["impute_median", { name = "poly", degree = 2 }, "standardize"]

[model]
name = "ridge"
lambda_ = 1e-3

[grid]          # optional: `cv` evaluates every combination (here 3 x 2 = 6)
"model.lambda_" = [1e-4, 1e-3, 1e-2]
"transforms.poly.degree" = [1, 2]
```

```bash
uv run p1 cv ridge_poly                          # k-fold CV of a preset (every grid combination)
uv run p1 cv baseline ridge_poly logistic        # compare several presets in one table
uv run p1 cv configs/ablation/*.toml             # ablation study = a folder of presets
uv run p1 cv ridge_poly --set model.lambda_=0.1  # override any value without editing the file
uv run p1 train ridge_poly                       # fit on all training data → outputs/models/
uv run p1 predict ridge_poly                     # → outputs/submissions/ridge_poly.csv
uv run run.py                                    # reproduce the best submission (configs/best.toml)
```

- To try several pairs, pass several presets. For a grid search, add a `[grid]` table. There's no separate "list of pairs" format to maintain.
- `cv` uses the same folds for every preset, so comparisons are fair. It prints a ranked table and appends every result to `outputs/cv_results.csv`, so all experiments end up in one file for the report.
- `[grid]` is only used by `cv`. `train` uses the plain values, so after a search, write the winning values into the preset.
- A new transform or model is a small class (`fit`/`transform` or `fit`/`predict`) plus one line in the name → class dict at the bottom of `transforms.py` / `models.py`. Every preset can then use it.

**uv.** `uv sync` creates or updates `.venv` from `pyproject.toml` + `uv.lock` (commit both). Run everything with `uv run …`, with no activation needed. In VS Code, pick `.venv` as the notebook kernel. Add packages with `uv add <pkg>`, or `uv add --dev <pkg>` for tools. The runtime dependencies are only `numpy` and `matplotlib` because of the course rules. Seaborn is allowed but pulls in pandas, so it's left out. The dev tools are `ipykernel` (notebooks), `black` (formatting), and `pytest` + `gitpython` (to run `grading_tests/`).

**The files the graders look for stay at the root:** `implementations.py`, `run.py`, `README.md`. The autograder imports `implementations.py` from the root, in its own Python 3.9 + NumPy 1.23 environment where our package isn't installed. So that file must be self-contained, and today's `utils.py` gets merged into it. `helpers.py` stays exactly as the course provided it.

### 4. Module contracts
Conventions:
- Inside `p1`, labels are `y ∈ {0, 1}` (converted on load). `{-1, 1}` only appears in submission files. Positives are 28,975 / 328,135 (8.8%), so F1 depends heavily on `threshold`, which is a model kwarg and can be put in a grid.
- A dataset is a `Dataset` dataclass (in `data.py`) with fields `x_train, y_train, x_test, train_ids, test_ids, feature_names`, for raw and clean data alike.
- Every path comes from `paths.py`, never relative to the cwd (notebooks run from `notebooks/`).

Modules:
- `paths.py`: `ROOT = Path(__file__).resolve().parent.parent`; `RAW_DIR, RAW_ZIP, RAW_CACHE, CLEAN_DATA, CONFIGS_DIR, OUTPUTS_DIR, CV_RESULTS, MODELS_DIR, SUBMISSIONS_DIR, FIGURES_DIR`.
- `data.py`:
  - `load_raw()`: if the CSVs are missing, extract `RAW_ZIP` (its members sit under `dataset/`, so flatten them). Parse with `helpers.load_csv_data`, take feature names from the CSV header (minus `Id`), and cache to `RAW_CACHE` with `np.savez` because `genfromtxt` is slow.
  - `load_clean()`: if `CLEAN_DATA` is missing, raise `FileNotFoundError` pointing to `notebooks/02_cleaning.ipynb`. Warn if `cleaning.py` is newer than it. It doesn't build the file itself because `cleaning` imports `data`, so importing `cleaning` back would be circular.
  - `write_submission(ids, y01, path)`: map labels to `{-1, 1}`, then call `helpers.create_csv_submission`.
- `cleaning.py`: `clean(x, feature_names) -> (x, feature_names)` is pure and deterministic, fits nothing, and is applied identically to train and test. `build_clean_dataset()`: `load_raw` → `clean` both → save `CLEAN_DATA`.
- `eda.py`: matplotlib and summary helpers for the notebooks. Part-3 code never imports it.
- `transforms.py`:
  - Base `Transform` with `fit(x, y=None) -> self` (no-op by default), `transform(x)` and `fit_transform`.
  - Hyper-parameters are `__init__` kwargs (= preset keys). Fitted state lives in trailing-underscore attributes (`self.mean_`).
  - Start with `impute_median`, `standardize`, `whiten` and `poly` (per-feature powers, no cross terms). At the bottom: `TRANSFORMS = {"standardize": Standardize, ...}`.
- `models.py`:
  - Base `LinearModel(threshold=0.5)`. `fit(x, y)` prepends the bias column and calls `_fit_weights(y, tx) -> w`. `predict_score(x)` (logistic models apply the sigmoid). `predict(x) = (score >= threshold).astype(int)`.
  - One subclass per mandatory function, calling `implementations.*` with `initial_w = zeros`. Non-linear models only need `fit`/`predict_score`/`predict`.
  - At the bottom: `MODELS` maps `least_squares, ridge, mse_gd, mse_sgd, logistic, reg_logistic, …` to their classes.
- `pipeline.py`:
  - `Pipeline(transforms, model, seed)`. `fit` starts with `np.random.seed(seed)` (the mandatory SGD uses NumPy's global RNG), then fit_transforms each step and fits the model. It also has `predict` and `predict_score`.
  - `build_pipeline(config, feature_names=None)`: a string item becomes the class with defaults, a table item becomes `name` + kwargs, and an unknown name raises an error listing the valid names.
  - Transforms with a `columns` option (feature names) get those resolved to indices here, and must come before any step that changes the number of columns.
  - Training-only row operations (e.g., undersampling negatives) go in `Pipeline.fit` via a preset key, never in a transform, because transforms also run at inference.
- `evaluation.py`: `f1_score`, `accuracy`, `kfold_indices(n, k, seed)`, `cross_validate(config, ds) -> {f1_mean, f1_std, acc_mean, acc_std, seconds}` with a fresh pipeline per fold. The same seed gives the same folds for every config (a paired comparison for ablations).
- `config.py`:
  - `DEFAULTS = {seed: 42, k_folds: 5, subsample: 1.0, transforms: []}`. `subsample` is the fraction of training rows that `cv` uses, for quick iterations.
  - `load_config(arg)`: a `*.toml` argument is a path, anything else means `configs/<arg>.toml`. The result is merged over the defaults; `name` defaults to the file stem.
  - `apply_overrides(config, ["a.b=v", ...])`: parse the value as TOML (`tomllib.loads(f"v = {raw}")["v"]`) and fall back to a string. Checked: `0.1`, `3`, `[1, 2]` and `ridge` all parse as intended. Key paths are top-level keys, `model.<key>` and `transforms.<name>.<key>` (a string item is promoted to a table).
  - `expand_grid(config) -> list[dict]`: cartesian product of `[grid]`, with variants named like `ridge_poly[degree=2,lambda_=0.001]`. Without a grid it returns `[config]`.
- `cli.py`: argparse subcommands. The command functions (`run_cv`, `train`, `predict`) are importable.
  - `cv PRESET... [--set K=V]...`: load the data once. For each preset: load → override → expand → `cross_validate`. Print a ranked table and append rows to `CV_RESULTS` (columns `timestamp, name, f1_mean, f1_std, acc_mean, acc_std, k_folds, subsample, seconds, config`, with `config` as JSON).
  - `train PRESET... [--set K=V]...`: print that `[grid]` is ignored, fit on all the training data, pickle to `MODELS_DIR/<name>.pkl`, and write the resolved config to `<name>.json`.
  - `predict NAME...`: unpickle, predict `x_test`, write `SUBMISSIONS_DIR/<name>.csv`.
- `run.py`: keep it readable top to bottom, because graders read it. `build_clean_dataset()` → `load_clean()` → `load_config("best")` → `build_pipeline` → fit on all training data → write `outputs/submissions/best.csv` and print the path. It retrains instead of loading a pickle: retraining is fast for linear models, and NumPy-2 pickles don't load under NumPy 1.x. The README should say to run it with `uv run run.py` (uv fetches a suitable Python); plain `python run.py` needs Python ≥ 3.11 + NumPy.
- `configs/best.toml`: frozen copy of the config behind the best AIcrowd submission. Never edit it after submitting.

### 5. Course constraints
- Repo code uses only the stdlib and NumPy (plus matplotlib for plots).
- `implementations.py`:
  - Use the exact Table 1 signatures and return `(w, loss)`, where `loss` is a 0-d float computed for the returned `w` (also when `max_iters = 0`).

  - Docstrings on every function, no `np.linalg.lstsq`, 1-D arrays.
